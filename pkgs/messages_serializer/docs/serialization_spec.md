# Messages Serialization Format Specification

Version: `0`

This specification describes the JSON data payload format generated by `package:messages_serializer` and consumed by `package:messages` (`JsonDeserializer` / `MessageListJson`).

---

## 1. Top-Level Structure

A serialized message bundle is represented as a single JSON array (`List<dynamic>`):

```json
[
  <serialization_version>,
  <locale>,
  <hash>,
  <index_mapping>,
  <message_0>,
  <message_1>,
  ...
]
```

### Preamble Fields (Indices 0..2)

| Index | Field | Type | Description |
|-------|-------|------|-------------|
| `0` | `version` | `int` | Format version number. Must match `serializationVersion` (currently `0`). |
| `1` | `locale` | `String` | Target BCP47/ICU locale string (e.g., `"en_US"`, `"de"`). |
| `2` | `hash` | `String` | 8-character SHA-1 digest prefix of the input source bundle. |

### Index Mapping (Index 3)

| Index | Field | Type | Description |
|-------|-------|------|-------------|
| `3` | `mapping` | `List<int>?` | Integer array of original kept message indices `[orig_index_0, orig_index_1, ...]` when messages are shrunk (`keepOnly`); `null` if all original messages are present in sequence. |

---

## 2. Message Encodings (Index 4+)

Messages are serialized recursively using type identifiers or compact string forms.

### Type Identifiers

| Type Code | Message Class | Description |
|-----------|---------------|-------------|
| *(implicit)* | `StringMessage` | Inferred when array element 0 is a `String` (no type header required). |
| `3` | `PluralMessage` | Plural logic branch message. |
| `4` | `SelectMessage` | Selection/gender switch message. |
| `6` | `CombinedMessage` | Concatenated list of sequential submessages. |

---

### A. String Message (`StringMessage`)

1. **Simple Form** (No placeholders):
   Represented as a plain JSON string:
   ```json
   "Hello World"
   ```

2. **Full Form** (With placeholders):
   ```json
   [ <message_value>, [ <string_index_1>, <arg_index_1> ], [ <string_index_2>, <arg_index_2> ], ... ]
   ```

   - `message_value` (`String`): Raw template string.
   - Placeholder insertions (`[ <string_index>, <arg_index> ]`): A 2-element integer array indicating string character offset where argument `arg_index` should be substituted. Position pairs **must** be sorted by `string_index` ascending.

---

### B. Plural Message (`PluralMessage`)

Type Code: `3`

```json
[ 3, <arg_index>, <other_message>, [ <marker_1>, <case_message_1>, ... ] ]
```

- `arg_index` (`int`): Zero-based index of argument evaluating quantity.
- `other_message` (`dynamic`): Fallback encoded submessage for unmatched plural categories.
- `cases_array` (`List<dynamic>`): Flattened pairs of `[ marker, encoded_message ]`:
  - **Explicit Number Cases** (`=0`, `=1`, `=2`): Encoded as JSON `int` (`0`, `1`, `2`).
  - **Word Cases** (`zero`, `one`, `two`): Encoded as JSON `String` prefixed with `"w"` (`"w0"`, `"w1"`, `"w2"`).
  - **Category `few`**: String `"f"`.
  - **Category `many`**: String `"m"`.

---

### C. Select Message (`SelectMessage`)

Type Code: `4`

```json
[ 4, <arg_index>, <other_message>, { "<case_key_1>": <case_message_1>, ... } ]
```

- `arg_index` (`int`): Zero-based index of argument evaluating selection.
- `other_message` (`dynamic`): Fallback encoded submessage for unmatched case key.
- `cases_map` (`Map<String, dynamic>`): Key-value map from selector case string (e.g. `"female"`, `"male"`) to encoded submessage.

---

### D. Combined Message (`CombinedMessage`)

Type Code: `6`

```json
[ 6, <submessage_1>, <submessage_2>, ... ]
```

- Combines two or more sequential submessages into a single formatted result string by concatenating their outputs in order.

---

## 3. Future Refinements (Candidate Format v1 Ideas)

1. **Flattened Placeholder Positions**:
   Instead of wrapping each placeholder in an array (`[ [offset1, arg1], [offset2, arg2] ]`), position pairs could be flattened into a single list `[offset1, arg1, offset2, arg2]`, saving 2 bracket bytes per placeholder.
2. **Flattened Select Cases**:
   `SelectMessage` could use a 1D list `["female", female_msg, "male", male_msg]` instead of a JSON map, eliminating JSON object `{}` overhead.
3. **Optional Preamble Slot**:
   If index 3 (`mapping`) is `null` for unshrunk bundles, allowing preamble element 3 to be omitted entirely when `mapping` is empty would eliminate 5 bytes (`null,`) per message bundle.
